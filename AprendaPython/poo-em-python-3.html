    Programção Orientada a Objetos em Python - Parte 3

    Encapsulamento: Getters, Setters e Property

    Como explicado, o encapsulamento visa manter a integridade do sistema, protegendo o estado interno do objeto contra interferência externa não regulamentada. No caso do Python nós apenas sinalizamos quais atributos devem ser considerados protegidos ou privados. Para podermos manipular os atributos protegidos e privados precisaremos criar métodos públicos conhecidos como getters e setters, que controlarão o acesso de forma mais segura.

    Voltando ao exemplo da conta bancária, nós não teremos acesso direto ao cofre pra colocar e pegar dinheiro, para isso teremos um funcionário do banco para poder fazer isso de forma controlada, esse é o conceito de métodos acessores.

    No Python existem duas maneiras de permitir o acesso aos dados encapsulados: O uso de getters e setters, e o uso do decorador @property.

    O exemplo de getters e setters poderia ser, por exemplo, na nota de um aluno, cuja nota seria protegida, para apenas pegar o valor da nota, usamos um getter, da mesma forma, para mudar, usamos um setter.

    Vamos supor esse código:

    
from rich import print, inspect

class Avaliacao:
    def __init__(self, nome, disciplina, nota = 0):
        self.nome = nome
        self.disciplina = disciplina
        self.nota = nota # Por enquanto deixe público

    Código principal:

    
def main():
    av1 = Avaliacao("Sérgio", "Matemática", 9.5)
    inspect(av1)

if __name__ == "__main__":
    main()

    Só que isso poderá dar erros, como por exemplo:

    
av1 = Avaliacao("Sérgio", "Matemática", 9.5)

av1.nota = -234 # Não deveria permitir

inspect(av1)

    Aí, na classe, colocamos o atributo nota como protegido, assim:

    
self._nota = nota

    E exiba assim:

    
av1 = Avaliacao("Sérgio", "Matemática", 9.5)

av1.nota = -234

inspect(av1, private = True)

    Nesse caso acima, ele protegeu o atributo nota da classe, e deixou a nota exposta no código principal isolada.

    Para criar os métodos getter (que pega) e setter (que muda), alteramos a classe assim:

    
class Avaliacao:
    def __init__(self, nome, disciplina, nota = 0):
        self.nome = nome
        self.disciplina = disciplina
        self._nota = nota
    
    # Métodos acessores
    def getNota(self): # Método público getter, pega a nota
        return self._nota
    
    def setNota(self, valor): # Método público setter, muda a nota
        self._nota = valor

    PS: Esses nomes são os mais usados, mas eles podem ter qualquer nome.

    Só que tem um porém, através dos métodos setters poderemos mudar o atributo privado diretamente:

    
av1 = Avaliacao("Sérgio", "Matemática", 9.5)

av1.setNota(-234)

inspect(av1, private = True)

    Então, nesse caso, podemos personalizar o setter, dessa forma:

    
def setNota(self, valor): # Método público setter, muda a nota
    if valor >= 0 and valor <= 10:
        self._nota = valor
    else:
        print("Nota Inválida!")

    Se ele passar um valor fora do intervalo, ele não alterará:

    
av1 = Avaliacao("Sérgio", "Matemática", 9.5)

av1.setNota(10) # Passe valores válidos e inválidos

inspect(av1, private = True)

    Para usar o getter, basta usar ele num print ou atribuir o valor de retorno a outra variável:

    
av1 = Avaliacao("Sérgio", "Matemática", 9.5)

av1.setNota(10)
print(av1.getNota())

print(f"{av1.nome} tirou {av1.getNota()} em {av1.disciplina}.")

inspect(av1, private = True)

    Podemos usar o decorador @property em Python e outras linguagens modernas para acessar atributos protegidos e privados. Nesse caso usamos atributos especiais com esse indicador para validar o atributo. Vamos alterar o código da classe assim:

    
class Avaliacao:
    def __init__(self, nome, disciplina, nota = 0):
        self.nome = nome
        self.disciplina = disciplina
        self._nota = nota

    # Criando Atributos Validáveis:
    @property
    def nota(self): # Esse método funcionará como um atributo que pega o valor
        return self._nota

    @nota.setter # Nome do property, mesmo nome do atributo sem underline
    def nota(self, valor): # Esse método funcionará como um atributo que muda o valor
        if valor >= 0 and valor <= 10:
            self._nota = valor
        else:
            print("Nota Inválida!")

    E no código principal:

    
av1 = Avaliacao("Sérgio", "Matemática")

av1.nota = 3.5 # Como um setter, tente passar valores válidos e inválidos
print(av1.nota) # Como um getter

print(f"{av1.nome} tirou {av1.nota} em {av1.disciplina}.") # Como um getter

inspect(av1, private = True)

    PS: Além de setter, podemos ver o decorador getter, como por exemplo, no caso acima, seria @nota.getter, e temos também o deleter, como o @nota.deleter, dessa forma:

    
@nota.deleter
def nota(self):
    pass

    Atributos e Métodos Estáticos

    Atributos e métodos estáticos não pertencem a um objeto, e sim à própria classe. Nós podemos chamar eles diretamente pelo nome da classe no programa principal.

    Veja um exemplo de classe somente com métodos e atributos estáticos:

    
class Lampada:
    __preco = 9.50 # Simulação de estático
    __acesa = False
    
    @staticmethod
    def custo(): # Método estático não tem self, atributos também não
        print("A lâmpada custa R${:.2f}.".format(Lampada.__preco))
    
    @staticmethod
    def acender():
        print("A lâmpada está acesa!")
        Lampada.__acesa = True
    
    @staticmethod
    def apagar():
        print("A lâmpada está apagada!")
        Lampada.__acesa = False

    E o uso:

    
from Lampada import Lampada

Lampada.custo() # Método estático.

Lampada.acender()
Lampada.apagar()

Lampada.__custo = 8.25 # Atributo estático, não poderia ser acessado por ser "privado"

    PS: Métodos estáticos só podem trabalhar outros métodos e atributos quando estes também forem estáticos, e não podem ser sobrepostos. E atributos estáticos é recomendável eles serem inicializados.

    Polimorfismo: Override, Overload e Duck Typing

    Polimorfismo significa muitas formas, o polimorfismo é a propriedade ou estado daquilo que se apresenta e/ou se comporta de várias formas diferentes. É um único nome, mas com comportamentos diferentes.

    O polimorfismo é o mesmo nome para coisas diferentes, vamos pegar por exemplo o pato, que é uma ave que pode andar, nadar e voar, o objeto pato tem o método locomover, que será diferente dependendo de onde ele está (na terra anda, na água nada e no ar voa).

    Vamos supor por exemplo, a função len do Python, que mostra a quantidade de caracteres de uma string, mas se passarmos uma tupla ou lista com duas string, ele conta a quantidade de itens, por exemplo:

    
len("Gustavo") # Retorna 7 (quantidade de caracteres)
len(("Sandy", "Júnior")) # Retorna 2 (quantidade de itens)
len({"a": "x", "b": "y"}) # Retorna 2 (quantidade de itens)

    No caso acima, o len teve comportamentos diferentes ao passar string, tupla e dicionário. É um exemplo de function overload (ou função de sobrecarga).

    No Python temos também o operador, onde o operador + tem comportamentos diferentes:

    
+5 # Mostra 5 positivo
5 + 4 # O + Soma números
"Poli" + "Morfo" # O + Concatena strings
[3, 5] + [2, 4] # O + Concatena os números das listas, sem somar

    Veja um exemplo com o método len:

    
print(len("Gustavo Guanabara")) # String
print(len(("Curso", "Python"))) # Tupla
print(len({"nome": "Maria", "idade": 22})) # Dicionário

    E com operadores:

    
print(+12) # Mostra 12 positivo
print(5 + 2) # Mostra a soma
print("Poli" + "morfismo") # Concatena
print([1, 3, 4] + [9, 7]) # Une as listas

    Para criarmos nossos próprios exemplos de polimorfismo em classes, vamos exemplificar com quatro animais: Pato, cachorro, gato e galinha. Todos eles terão o método exibirSom(), mas cada um emite o som de forma diferente Vamos supor essas classes, que todas elas herdam da classe abstrata Animal, com o método descrito abstrato:

    
from abc import ABC, abstractmethod

class Animal(ABC):
    def __init__(self, nome:str = ""):
        self.nome = nome

    def emitirSom(self):
        print(f"{self.nome} é {self.__class__.__name__.lower()} e está emitindo um som.")

class Pato(Animal):
    pass

class Cachorro(Animal):
    pass

class Gato(Animal):
    pass

class Galinha(Animal):
    pass

    E o código principal:

    
def main():
    a = Cachorro("Bandit")

    a.emitirSom()

    b = Gato("Frajola")

    b.emitirSom()

if __name__ == "__main__":
    main()

    Deixe as classes específicas assim:

    
class Pato(Animal):
    pass

class Cachorro(Animal):
    def emitirSom(self):
        print(f"{self.nome} acabou de dizer: \"Au! Au! Au!\"")

class Gato(Animal):
    def emitirSom(self):
        print(f"{self.nome} acabou de dizer: \"Miau! Miau!\"")

class Galinha(Animal):
    pass

    Com esses objetos:

    
a = Cachorro("Bandit")
b = Gato("Frajola")
c = Pato("Donald")

a.emitirSom()
b.emitirSom()
c.emitirSom()

    No caso acima, as classes Cachorro e Gato sobrescreveram (substituíram) o método da classe Animal, no entanto isso não acontece com o Pato, que mostra o método original de Animal. Isso e o polimorfismo de sobreposição ou de inclusão (quando usado com métodos e classes abstratos).

    Podemos inclusive deixar o método da classe Animal abstrato, assim:

    
@abstractmethod
def emitirSom(self):
    pass

    Só que nesse caso, todas as classes que herdarem dessa classe abstrata, deverão implementar todos os métodos abstratos descritos. No caso fica assim:

    
class Pato(Animal):
    def emitirSom(self):
        print(f"{self.nome} acabou de dizer: \"Quac! Quac! Quac!\"")

class Cachorro(Animal):
    def emitirSom(self):
        print(f"{self.nome} acabou de dizer: \"Au! Au! Au!\"")

class Gato(Animal):
    def emitirSom(self):
        print(f"{self.nome} acabou de dizer: \"Miau! Miau!\"")

class Galinha(Animal):
    def emitirSom(self):
        print(f"{self.nome} acabou de dizer: \"Có! Có! Có!\"")

    Com esses objetos assim:

    
a = Cachorro("Bandit")
b = Gato("Frajola")
c = Pato("Donald")
d = Galinha("Clara")

a.emitirSom()
b.emitirSom()
c.emitirSom()
d.emitirSom()

    Como sabemos, podemos ter uma hierarquia de classes, e todas podem ter polimorfismo, vamos supor essas especializações de Cachorro:

    
class Spitz(Cachorro):
    pass

class Pitbull(Cachorro):
    pass

    Com esses objetos:

    
a = Cachorro("Bandit")
b = Gato("Frajola")
c = Pato("Donald")
d = Galinha("Clara")
e = Spitz("Luluzinha")
f = Pitbull("Guerreiro")

a.emitirSom()
b.emitirSom()
c.emitirSom()
d.emitirSom()
e.emitirSom()
f.emitirSom()

    No caso acima, Spitz e Pitbull, como também são cachorros, executam o mesmo método da classe mãe Cachorro. Mas também podemos especializar elas, assim:

    
class Spitz(Cachorro):
    def emitirSom(self):
        print(f"{self.nome} acabou de dizer: \"Auauauauauauauau!\"")

class Pitbull(Cachorro):
    def emitirSom(self):
        print(f"{self.nome} acabou de dizer: \"Ruf! Ruf! Ruf!\"")

    O código principal permanece o mesmo.

    Esse tipo de polimorfismo é o de inclusão, override ou sobreposição, e este exige herança. Outros tipos de polimorfismo são o de sobrecarga, coerção (que é a conversão automática de tipos de dados) e paramétrico (usando templates genéricos), só que os dois últimos não são suportados no Python, mas existem em outras linguagens.

    Veja outro exemplo:

    
class Mae:
    def __init__(self, nome:str = "Mamãe"):
        self.nome = nome

    def fazerPudim(self):
        print(f"{self.nome} faz pudim com leite condensado e calda!")

    def fritarCoxinha(self):
        print(f"{self.nome} frita coxinha no óleo de soja!")

class Filha(Mae):
    pass

class Filho(Mae):
    pass

    Com esses objetos:

    
def main():
    p1 = Mae("Jaci")
    p2 = Filho("Matt")
    p3 = Filha("Mônica")
    
    p1.fazerPudim()
    p1.fritarCoxinha()
    
    p2.fazerPudim()
    p2.fritarCoxinha()
    
    p3.fazerPudim()
    p3.fritarCoxinha()

if __name__ == "__main__":
    main()

    Mas isso acima não é polimorfismo, pois todos fazem pudim e fritam coxinha de maneiras iguais. Para fazer o polimorfismo, fazemos assim:

    
class Filha(Mae):
    def fazerPudim(self):
        print(f"{self.nome} faz pudim com Leite Ninho com Nutella!")

class Filho(Mae):
    def fritarCoxinha(self):
        print(f"{self.nome} frita coxinha na air fryer!")

    Os objetos no código principal não serão alterados, mas os métodos se comportarão de formas diferentes.
