Dicas sobre Bancos de Dados SQL

Pensando em SQL e transações, dá para resumir as transações assim:

Tipo Significa Para que Serve Exemplos
DDL Data Definition Language Cria/altera a estrutura do banco create, alter, drop
DML Data Manipulation Language Manipula os dados insert, update, delete
DQL Data Query Language Consulta os dados select
DCL Data Control Language Controla permissões e acessos grant, revoke
DTL Data Transaction Language Controla transações commit, rollback, savepoint

Jeito fácil de lembrar:

  • DDL → Estrutura → "Criar a tabela".
  • DML → Dados → "Inserir/alterar/excluir registros".
  • DQL → Consultar → "Buscar informações".
  • DCL → Controle → "Quem pode fazer o quê".
  • DTL → Transação → "Confirmar ou desfazer operações".

PS: A classificação pode variar um pouco entre materiais/bancos, por exemplo, alguns tratam select como parte da DML em vez de separar DQL.

A sigla DICA são as propriedades de uma transação no banco de dados:

  • D (Durabilidade): Depois do commit, os dados ficam salvos, mesmo se houver uma falha.
  • I (Isolamento): Uma transação não interfere indevidamente em outra.
  • C (Consistência): A transação mantém o banco em um estado válido.
  • A (Atomicidade): Ou tudo acontece, ou nada acontece.

Resumindo: DICA garante que uma transação seja segura, correta e confiável.
